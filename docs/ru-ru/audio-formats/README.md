# Аудиоформаты

## Форматы с потерями и без потерь

Я стараюсь получить максимально возможное качество релизов, поэтому почти вся моя библиотека состоит из файлов в формате без потерь.  
Используемый кодек без потерь: `FLAC`, энкодер: [libFLAC v1.5.0](https://xiph.org/flac/download.html), уровень сжатия: 8.  
При конвертации из других форматов без потерь (`ALAC`, `WAV`) во `FLAC` я сохраняю оригинальную битовую глубину и частоту дискретизации.

Если я не смог получить релиз в формате без потерь, то тогда я стараюсь получить самый высококачественный релиз в формате с потерями с учетом кодека и битрейта.

При передаче релизов в формате без потерь на устройства с небольшим количеством памяти (например, телефон) они конвертируются в кодек `Opus`. Используемый энкодер: [libopus v1.6.1](https://opus-codec.org/release/stable/2026/01/14/libopus-1_6_1.html), выбранный битрейт: `192 kbps VBR`.  
Релизы в формате с потерями не конвертируются при передаче на устройства.

## Контрольные суммы

Я использую контрольные суммы `MD5` только для `FLAC`, поскольку в его заголовок `STREAMINFO` уже встроена контрольная сумма незакодированных аудиоданных (подробнее смотрите в [спецификации FLAC (RFC 9639, раздел 8.2. Streaminfo)](https://www.rfc-editor.org/rfc/rfc9639.html#name-streaminfo)). Это дает возможность проверять целостность самого аудиопотока независимо от изменений метаданных.  
Другие форматы без потерь я конвертирую в `FLAC`, поэтому они здесь не рассматриваются.  

Для форматов с потерями сверка контрольных сумм декодированного потока бессмысленна из-за недетерминированности. Из-за различий в компиляторах, архитектурах, реализаций внутри самих кодеков (например, в `Opus` есть реализация с фиксированной точкой и с плавающей запятой - fixed-point и floating-point, подробнее смотрите в [файле README репозитория Opus на GitHub](https://github.com/xiph/opus/blob/main/README) в разделе Portability notes), декодерах, настройках конвертации и еще много каких переменных, декодированный вывод PCM не обязательно каждый раз будет одинаковым, что лишает проверку целостности смысла.

Я также не использую контрольные суммы для всего файла, потому что изменения в метаданных, обложке, отступах между тегами, или других данных, не связанных со аудиопотоком, изменили бы эту контрольную сумму, даже если бы сам аудиопоток остался идентичным.
